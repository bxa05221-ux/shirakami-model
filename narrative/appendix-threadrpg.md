# 付録　ThreadRPG――白神高校ブラスバンド部の対話構造

『白神高校ブラスバンド部』には、物語として読むだけでは見えにくい、もう一つの構造がある。

それは、登場人物の会話を「答えを出すための会話」ではなく、「同じ世界を別々の位置から観測し、その観測を時間の中につないでいく会話」として読む構造である。

この構造を、ここでは **ThreadRPG** と呼ぶ。

## 一つのLandscape

ThreadRPGの中心にあるのは、個々の人物ではない。

全員が共有しているLandscape――その時点で見えている出来事、関係、記録、まだ言葉になっていない違和感、そして未解決の問い――である。

会話は、このLandscapeに対する観測として積み重なる。

## 七つの観測点

物語の人物を、固定された「専門家」や、それぞれ独立したAI人格として考える必要はない。

ThreadRPGでは、同じLandscapeを七つの観測点から眺める。

同じ出来事でも、観測点が変われば見えるものが変わる。

重要なのは、七人がそれぞれ正しい答えを持っていることではない。

**一つの答えに急いで収束しないこと**そのものが、この構造の一部になっている。

## Thread――時間につながる観測

一回の会話で終わらせない。

ある時点の観測を残し、別の時点で再び眺める。

その間に新しい出来事が起きれば、以前の言葉の意味が変わって見えることもある。

Threadとは、過去を上書きすることではなく、観測と観測の間を時間によってつなぐことである。

## 暗問層――まだ答えなくていい問い

会話の中で生まれた問いは、すぐに解決しなくてもよい。

まだ判断できないもの、情報が足りないもの、なんとなく気になるだけのもの。

そうした問いを置いておく場所が暗問層である。

問いを消さず、答えを捏造せず、必要になったときにもう一度眺める。

## 雨水モード

暗問層に沈んだ問いが増えたとき、過去の観測をつなぎ直す動きを強めることがある。

それが雨水モードである。

雨水は、降ったその場で答えになるわけではない。

いったん地面にしみ込み、別の場所から現れ、時間を置いて流れをつくる。

ThreadRPGにおける雨水モードも同じで、未解決の問いを無理に解決するのではなく、再観測と接続を促す。

## Revisit――もう一度見る

以前の問いを、以前と同じ答えで閉じるためではなく、現在のLandscapeからもう一度観測する。

新しい情報によって、問いそのものの形が変わることもある。

## Catch――釣り上げるのは誰か

ThreadRPGには、システムが「これが正解です」と宣言する終点を置かない。

最後に「あ、これだったのか」と釣り上げるのは、人間である。

AIやRuntimeができるのは、観測し、整理し、つなぎ、再び眺めるところまで。

Catchは、人間自身の発見と判断として残される。

## 物語からアーキテクチャへ

この構造は、物語の中だけに閉じる必要がない。

```text
『白神高校ブラスバンド部』
          ↓
       ThreadRPG
          ↓
 Shirakami Architecture
          ↓
       SHBB API
          ↓
 Runtime / Model Provider
```

小説が先にあり、その中に現れていた対話構造をThreadRPGとして取り出す。

ThreadRPGをさらに一般化すると、Shirakami Architectureになる。

そして、その構造を機械から扱える入口として切り出したものがSHBB APIである。

つまり、APIのために物語を作ったのではない。

**物語にすでに存在していた構造を、別の言語へ移したのである。**

この付録は、その移植のための技術マニュアルではない。

小説をもう一度読むための、もう一つの読み方である。

それがThreadRPGである。
